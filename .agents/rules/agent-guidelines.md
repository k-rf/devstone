# Agent Guidelines

## 1. スキルとルールの定義と役割

エージェントを構成・カスタマイズするにあたり、「スキル」と「ルール」は明確に役割を分離して定義します。

### スキル（Skill）: ふるまいと手順

- **定義**: エージェントが実行する具体的な手順や、振る舞いを記述したものです。
- **性質**: 「実行する」ものであり、目的を達成するための道具や手段として機能します。

### ルール（Rule）: 作法と境界

- **定義**: エージェントがやってはいけないこと（禁止事項）や、推奨することを記述したものです。
- **性質**: 「守る」ものであり、エージェントの行動を制御し、安全に開発を進めるための境界線として機能します。

## 2. コマンド実行の規律（単一コマンド実行の原則）

コマンド実行時の自動承認（プレフィックス一致による許可判定）が阻害されるのを防ぐため、シェルコマンドを実行する際は、以下のルールを厳守します。

- **パイプ（`|`）による連結の禁止**:
  コマンドの出力をパイプで別コマンド（`head`、`tail`、`grep`、`cat` 等）に渡してはなりません。
  出力の絞り込みや検索には、対象コマンド自身のオプション（例: `git log -n 10`）や、
  専用のファイル操作・検索ツール（`view_file`、`grep_search` 等）を使用してください。
- **演算子（`&&`、`||`、`;`）による複数コマンド連結の禁止**:
  1回のコマンド実行に複数のコマンドを連結して記述してはなりません。
  複数のコマンドを実行する必要がある場合は、1コマンドずつ個別のツール呼び出しに分けて実行してください。
- **コマンド置換・ヒアドキュメントの禁止**:
  `$(...)` やバッククォートによるコマンド置換、および `<<EOF` などのヒアドキュメント構文は
  自動承認を無効化するため使用せず、
  コマンドの引数オプション（例: `git commit -m "<見出し>" -m "<本文>"`）で直接指定してください。
