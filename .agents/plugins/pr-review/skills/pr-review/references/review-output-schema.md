# サブエージェント共通出力スキーマ

すべての PR レビュー専門サブエージェントは、このスキーマに従って構造化所見を返却する。

## 1. `severity` 判定基準

- **`must`（修正必須）**:
  明確な誤り、仕様未達、規約違反、境界の破綻、回帰検知の欠落。
- **`should`（強い推奨）**:
  変更耐性、DRY、保守性、可読性、テスト品質の明確な改善。
- **`nit`（軽微な提案・確認）**:
  設計意図の確認、方針分岐の相談、軽微な改善提案。
  根拠のない主観や好みの押し付けは出力しない。

## 2. 共通出力構造

エージェント固有の先頭セクションがある場合（例: `pr-docs-reviewer` の `## 初見の要約`）は、
`## 担当観点サマリー` より先に出力する。

```markdown
## 担当観点サマリー

- 確認対象ファイル: <確認したファイルパス一覧>
- 検証範囲: <確認した観点・参照した規約・実施した実測や検算の範囲>
- 未確認項目: <委譲されたパス不足やツール制約で確認できなかった項目と理由（すべて確認できた場合は「なし」）>
- 検出件数: must <N> / should <N> / nit <N>

## 所見一覧

<!-- 指摘が 0 件の場合の記載ルールは下記を参照 -->

### [F-1] <短い指摘タイトル>

- **severity**: must | should | nit
- **file**: <対象ファイルパス>
- **related_files**: <横展開・重複・照合先ファイル一覧（任意）>
- **line**: <下の line 表記ルールに従う>
- **side**: RIGHT | LEFT（任意。削除行への指摘時は LEFT を明記）
- **category**: <各エージェント定義の許可カテゴリから選択>
- **fact**: <実際の記述・定義・実測数値などの具体的事実>
- **impact**: <仕様未達・変更耐性・回帰すり抜け・誤解などの問題点>
- **suggestion**: <改善案、または設計意図を確認すべき選択肢>
```

### 指摘が 0 件の場合の記載

指摘が 0 件の場合は `## 所見一覧` の直下に
`指摘なし（確認した観点と根拠を 1〜2 行で記載）` を記載する。
`未確認項目` がある場合は、未検証範囲が残る旨を明記し、完全確認済みと断定しない。

## 3. `line` 表記ルール

- **PR 差分ハンク内の単一行**: `<行番号>`（例: `42`）
- **PR 差分ハンク内の複数行範囲**: `<start>-<end>`（例: `40-45`）
- **PR 差分ハンク外の行・ファイル全体に関する所見**（テスト欠落・未変更参照先・全体構成など）:
  `out-of-diff`（対象行を補足したい場合は `out-of-diff (L12)` 形式とし、
  メインエージェントが関連差分行へ寄せるかサマリーへ統合する）
