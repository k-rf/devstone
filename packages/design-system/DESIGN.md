# Design System

本ドキュメントは、`@devstone` デザインシステムが目指す視覚・体験の原則と、UI 設計における判断基準を定義します。
具体的なデザイントークンの値（SSoT）については `@devstone/design-system-tokens` の実装コードを参照してください。

---

## 1. デザイン原則

自分用の開発・生産性ツールから、日常的に誰もが触れるミニアプリまで、一貫して心地よい体験を提供するための 4 つのコア原則です。

### 1.1. 飾るのではなく、構造を際立たせる

主役は UI ではなく、その中にある情報とコンテンツ。クセのある書体や意味のない装飾で目を引こうとせず、余白のリズム、素直な文字の階層、繊細な境界線だけで、視線が迷わず流れる画面をつくる。

### 1.2. 威圧せず、手に馴染む端正さ

業務システムのようなお堅い威圧感も、削ぎ落としすぎた無機質な冷たさも持ち込まない。
毎日向き合う自分用のツールから、体育館でパッと開くミニアプリまで、誰もが構えずに触れられる「理路整然としているのに、どこか柔らかい」佇まいを保つ。

### 1.3. 演出ではなく、確かな手応えを返す

波紋のような大げさなエフェクトで操作のテンポを奪わない。かといって、無反応で不安にもさせない。触れた瞬間、押した瞬間に、色と明度が小気味よく切り替わる「静かで確実な手応え」だけを返す。

### 1.4. 感覚に頼らず、仕組みで調和させる

読みやすさや美しさを、その場しのぎの微調整や個人の注意力に委ねない。
計算されたスケールと厳格なトークン契約によって、どのテーマ・どのモード（Light / Dark）を選んでも、最初から破綻のないコントラストと統一感が立ち上がるようにする。

---

## 2. 判断の天秤と輪郭

設計やスタイリングで迷ったときは、以下の優先順位と輪郭に立ち返って判断します。

### 天秤の傾き

1. **個性的なクセより、素直な読みやすさ**
   独特のフォントや装飾で主張するより、PC でもスマートフォンの小さな画面でも誰もが自然に読める書体と整った余白を選ぶ。
2. **派手な演出より、軽快で確実な手応え**
   自己主張の強いアニメーションは使わず、ホバーやタップに対して色や明度が素早く自然に変化する反応を返す。
3. **お堅い業務感より、親しみやすい端正さ**
   事務的な硬さや極端な情報の詰め込みを避け、秩序がありながらも呼吸感のある余白と穏やかな角丸をベースにする。

### 輪郭

| 目指す姿               | 避ける姿                                  |
| :--------------------- | :---------------------------------------- |
| **理路整然としている** | **冷たく素っ気ない** わけではない         |
| **親しみやすい**       | **ガチャガチャして騒がしい** わけではない |
| **手応えがある**       | **過剰な演出で邪魔をする** わけではない   |
| **きちんとしている**   | **お堅く威圧感がある** わけではない       |

## 3. トークン階層と責務の原則

デザイントークンは **`@devstone/design-system-tokens`** にて **Primitive** と **Semantic** の 2 層で管理し、
コンポーネント固有のスタイル割り当ては **`@devstone/design-system-react`** の各 React コンポーネントにカプセル化します。

1. **Primitive トークン（第 1 層：物理スケール・パレット）**
   - 意味や用途を持たない生のパレットおよび物理・数値ステップ
     （例：`color.slate.500`, `spacing.4`, `radius.8`, `font.size.16`, `duration.150`）。
   - キー名は Semantic 層とのねじれを防ぐため、相対名（`md` 等）ではなく物理・数値ステップを用いる。
   - UI コンポーネント層から直接参照してはならない。
2. **Semantic トークン（第 2 層：`ThemeContract`）**
   - 特定のコンポーネント名（`card`, `input`, `button` 等）や下流フレームワークの都合を一切持ち込まない。
   - カラー（`ColorThemeContract`）は **「役割（`bg` / `fg` / `border`）× 意味（ベース / `accent` / `status`）
     × 強弱（`default` / `emphasized` / `subtle` / `muted`）」** で構成する。
   - 色以外（`BaseThemeContract`）は **「意味階層・抽象スケール
     （`font`, `radius`, `spacing`, `borderWidth`, `duration`, `easing`）」** で構成する。
   - 各テーマは `BaseThemeContract` とモード別（`light` / `dark`）の `ColorThemeContract` を合成し、
     すべてのテーマ・モードが共通の `ThemeContract` を満たす純粋な DTCG ツリーとなる。
3. **Component スタイル（第 3 層：React コンポーネント実装）**
   - 独立した「コンポーネントトークン」の中間層は設けず、React コンポーネントのスタイル定義が Semantic トークンを直接参照する。
